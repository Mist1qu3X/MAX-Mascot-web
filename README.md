# MAX Mascot — страница стикера

Посетитель фотографируется на панели MAX, получает 3D-маскота и сканирует
QR-код. Код ведёт сюда: на страницу с картинкой, кнопкой «Сохранить» и
инструкцией, как сделать из неё стикер в MAX.

Сервер — один файл `server/index.mjs` на встроенных модулях Node, без
зависимостей. Он раздаёт страницу, принимает от панели готовые картинки,
держит их в памяти и отдаёт телефонам. Сама панель живёт в отдельном
репозитории — MAX-Mascot-PO.

Кнопка «Сохранить» отдаёт не исходный квадрат, а PNG 1080 × 1080: круг с
градиентной рамкой и маскотом, как на странице (фон круга rgb(12, 1, 25)),
за кругом тёмный фон страницы `#0d001a`, справа снизу белый логотип MAX с
надписью — `sticker/img/max-logo-white.png`. Картинку страница собирает
сама, в браузере, сразу после загрузки — к нажатию она уже готова. Логотип
поменяли — меняйте и имя файла (или он перепроверяется сам: картинки из
`/img/` сервер отдаёт с `no-cache`).

```
server/index.mjs     сервер
server/stats.mjs     статистика генераций в MySQL
sticker/index.html   страница (русский и английский, язык — по телефону)
sticker/fonts/       VK Sans Display, отдаётся по /fonts/
sticker/img/         логотип MAX для сохраняемой картинки, по /img/
Dockerfile           образ для Dokploy
docker-compose.yml   свой MySQL 8 для разработки (на хостинге не нужен)
.env.example         переменные окружения
```

## Запуск у себя

Нужен Node.js 20+:

```bash
npm install
npm start
```

Страница откроется на `http://localhost:8787`. Без `PUBLIC_URL` сервер
считает себя локальным: ссылки в QR строит от IP компьютера в Wi-Fi, и
телефон должен быть в той же сети.

## Деплой в Dokploy

1. **Создать приложение** (Application) и подключить этот репозиторий,
   ветка `main`.
2. **Тип сборки — Dockerfile**, путь `Dockerfile`.
3. **Переменные окружения** (Environment):
   - `PUBLIC_URL` — адрес страницы с https, без слэша в конце, например
     `https://mascot.alavenir.tech`;
   - `SHOT_TOKEN` — пароль. Тот же, что `VITE_STICKER_TOKEN` в
     `.env.local` панели;
   - `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASS` — база MySQL
     для статистики. На alavenir.tech их задаёт админ; без них статистика
     выключена, остальное работает.
4. **Домен** (Domains): ваш адрес, путь `/`, порт контейнера `8787`,
   HTTPS включён, сертификат Let's Encrypt. Запись A для домена должна
   смотреть на тот сервер, где развёрнуто приложение, — иначе домен
   ответит 404 и останется без сертификата. Сейчас лендинг работает на
   сервере `alavenir.tech` (177.1.183.241) по адресу `mascot.alavenir.tech`;
   поддомены `*.alavenir.tech` уже ведут на этот сервер.
5. **Deploy**. Проверка: `https://<домен>/health` отвечает
   `{"ok":true,…}`.

Остальные переменные необязательны — список и значения по умолчанию в
`.env.example`.

**Только один экземпляр.** Картинки хранятся в памяти процесса: при двух
репликах телефон может попасть не в тот контейнер, который получил
картинку. При перезапуске или новом деплое картинки стираются — QR,
выданные до этого, перестают открываться. На работу панели это не влияет.

## Подключение панели

В `.env.local` панели (репозиторий MAX-Mascot-PO):

```
VITE_STICKER_RELAY=https://mascot.alavenir.tech
VITE_STICKER_TOKEN=<тот же SHOT_TOKEN>
```

После правки перезапустить панель (или пересобрать). Если сервер не
отвечает, панель не ломается: QR ведёт прямо на картинку kie.ai.

## Что умеет сервер

| Запрос | Зачем |
| --- | --- |
| `GET /?i=/i/<id>` | страница стикера с картинкой |
| `GET /i/<id>` | сама картинка; если копия ещё не докачана — ждёт до 2.5 с, потом отправляет на первоисточник |
| `GET /fonts/<файл>.woff2` | шрифт страницы |
| `GET /img/<файл>.png` | логотип MAX для сохраняемой картинки |
| `GET /health` | проверка живости, состояние базы статистики (`stats`) и последние замеры скорости |
| `POST /stats/generations` | панель присылает строки статистики генераций, см. ниже |
| `POST /shot` | панель: «вот картинка на kie.ai, дай ссылку для QR» — отвечает сразу, качает фоном |
| `POST /i/<id>` | панель досылает свою копию картинки, чтобы не ждать kie.ai |
| `POST /upload` | панель кладёт снятый кадр, kie.ai потом скачивает его отсюда |
| `/kie/*` | прокси к `api.kie.ai`, если тот с панели недоступен; ключ присылает панель |

Все `POST` и `/kie/*` требуют `Authorization: Bearer <SHOT_TOKEN>`, если
пароль задан.

## Статистика генераций

Панель после каждой генерации записывает строку: номер, начало, конец,
статус. Локально — в `generations.csv` рядом с приложением, онлайн — через
`POST /stats/generations` в MySQL. Сама база доступна только из контейнеров
на хостинге, поэтому пишет её этот сервер.

Таблица `generations` создаётся при старте сервера (`CREATE TABLE IF NOT
EXISTS`, схема — в `server/stats.mjs`). Время — UTC.

| Колонка | Что |
| --- | --- |
| `gen_no` | номер генерации на панели |
| `started_at`, `finished_at` | начало и конец генерации |
| `duration_s` | длительность в секундах — база считает сама из начала и конца |
| `status` | `success`, `cancelled` (ушли, не дождавшись) или `error:<причина>`: `config`, `network`, `policy`, `gesture`, `timeout`, `api` |
| `source` | `panel` — приложение на панели, `web` — веб-версия |
| `uid`, `received_at` | служебные: защита от повторной отправки и время прихода на сервер |

Нет связи — панель держит строки в очереди и досылает, когда сервер
ответит; повтор той же строки база не задвоит. Записанное сервер пишет в
лог: `[статистика] записано 1 из 1: №42 panel success`.

Для разработки — свой MySQL: `docker compose up -d`, затем
`DB_HOST=127.0.0.1 DB_PORT=3307 DB_NAME=mascot DB_USER=mascot DB_PASS=mascot npm start`.
