# MAX Mascot — страница стикера

Посетитель фотографируется на панели MAX, получает 3D-маскота и сканирует
QR-код. Код ведёт сюда: на страницу с картинкой, кнопкой «Сохранить» и
инструкцией, как сделать из неё стикер в MAX.

Сервер — один файл `server/index.mjs` на встроенных модулях Node, без
зависимостей. Он раздаёт страницу, принимает от панели готовые картинки,
держит их в памяти и отдаёт телефонам. Сама панель живёт в отдельном
репозитории — MAX-Mascot-PO.

```
server/index.mjs     сервер
sticker/index.html   страница (русский и английский, язык — по телефону)
sticker/fonts/       VK Sans Display, отдаётся по /fonts/
Dockerfile           образ для Dokploy
.env.example         переменные окружения
```

## Запуск у себя

Нужен Node.js 20+:

```bash
npm start
```

Страница откроется на `http://localhost:8787`. Без `PUBLIC_URL` сервер
считает себя локальным: ссылки в QR строит от IP компьютера в Wi-Fi, и
телефон должен быть в той же сети.

## Деплой в Dokploy

1. **Создать приложение** (Application) и подключить этот репозиторий,
   ветка `main`.
2. **Тип сборки — Dockerfile**, путь `Dockerfile`.
3. **Переменные окружения** (Environment):
   - `PUBLIC_URL` — адрес страницы с https, без слэша в конце, например
     `https://sticker.alavenir.tech`;
   - `SHOT_TOKEN` — пароль. Тот же, что `VITE_STICKER_TOKEN` в
     `.env.local` панели.
4. **Домен** (Domains): ваш адрес, путь `/`, порт контейнера `8787`,
   HTTPS включён, сертификат Let's Encrypt. Запись A для домена должна
   смотреть на сервер Dokploy.
5. **Deploy**. Проверка: `https://<домен>/health` отвечает
   `{"ok":true,…}`.

Остальные переменные необязательны — список и значения по умолчанию в
`.env.example`.

**Только один экземпляр.** Картинки хранятся в памяти процесса: при двух
репликах телефон может попасть не в тот контейнер, который получил
картинку. При перезапуске или новом деплое картинки стираются — QR,
выданные до этого, перестают открываться. На работу панели это не влияет.

## Подключение панели

В `.env.local` панели (репозиторий MAX-Mascot-PO):

```
VITE_STICKER_RELAY=https://sticker.alavenir.tech
VITE_STICKER_TOKEN=<тот же SHOT_TOKEN>
```

После правки перезапустить панель (или пересобрать). Если сервер не
отвечает, панель не ломается: QR ведёт прямо на картинку kie.ai.

## Что умеет сервер

| Запрос | Зачем |
| --- | --- |
| `GET /?i=/i/<id>` | страница стикера с картинкой |
| `GET /i/<id>` | сама картинка; если копия ещё не докачана — ждёт до 2.5 с, потом отправляет на первоисточник |
| `GET /fonts/<файл>.woff2` | шрифт страницы |
| `GET /health` | проверка живости и последние замеры скорости |
| `POST /shot` | панель: «вот картинка на kie.ai, дай ссылку для QR» — отвечает сразу, качает фоном |
| `POST /i/<id>` | панель досылает свою копию картинки, чтобы не ждать kie.ai |
| `POST /upload` | панель кладёт снятый кадр, kie.ai потом скачивает его отсюда |
| `/kie/*` | прокси к `api.kie.ai`, если тот с панели недоступен; ключ присылает панель |

Все `POST` и `/kie/*` требуют `Authorization: Bearer <SHOT_TOKEN>`, если
пароль задан.
